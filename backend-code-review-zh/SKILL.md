# 后端代码质量审查

**深度优先于广度。** 找到关键路径，沿着它深挖。找到3个真问题胜过29个表面检查。

**顺藤摸瓜，而非逐项打勾。** 有价值的问题藏在调用链和跨层交互中，不在孤立函数里。先梳理关键路径，让它指引审查方向。

## 问题分级

| 标记 | 含义 | 行动 |
|------|------|------|
| ❌ CRITICAL | 安全漏洞、数据正确性、生产可用性风险 | 阻塞合并 |
| ⚠️ WARN | 建议改进 | 记录为跟进事项 |
| 💡 SUGGEST | 可选——更优写法、风格建议 | 作者可忽略 |
| ℹ️ INFO | 上下文信息 | — |
| ✅ GOOD | 值得肯定 | — |

**拦截原则**：只拦截不修会导致生产事故的问题。风格偏好和替代方案是 💡 SUGGEST，不是 ❌ CRITICAL。

## 执行

1. **梳理关键路径。** 识别入口点，追踪调用链，标记高风险节点——外部调用、事务边界、共享状态、写操作、错误分支。输出调用链摘要，这是审查中最有价值的部分。
2. **沿关键路径深挖。** 对每个高风险节点，推演具体的失败场景。对每个错误分支，追踪：错误被静默吞掉了？事务回滚了？资源释放了？
3. **跨维度关联检查。** 即使某些维度未被显式选中，调用链上存在高风险组合也要标记。
4. **缺失项检测。** 检查该有但没有的东西。

## 场景推演

对每个可疑点，用具体场景验证：

| 关注点 | 推演 |
|--------|------|
| 并发 | 100个请求同时执行——共享状态会怎样？ |
| 事务+外部调用 | RPC超时，DB回滚但下游已处理——状态一致吗？ |
| 幂等 | 调用3次——数据变成什么样？ |
| 数据增长 | 1亿行时，这个查询还能1秒返回吗？ |
| 资源释放 | 第X行报错——之前打开的连接/锁释放了吗？ |
| 缓存 | 读写之间缓存过期——会发生什么？ |
| 重试 | 第3次成功——前两次的副作用？ |
| 链路追踪 | 用户报bug——日志能定位到服务和代码行吗？ |

## 跨维度风险

| 组合 | 检查 |
|------|------|
| 事务 + 外部调用 | 事务内有RPC/MQ？调用失败时回滚？ |
| 并发 + 数据库 | 先查后改原子吗？TOCTOU？ |
| 幂等 + 重试 | 重复调用导致重复扣款/发货？ |
| 缓存 + 数据库 | 缓存淘汰策略正确？异常路径下一致？ |
| 消息队列 + 事务 | 发送和DB在同一事务？发送失败但DB已提交？ |
| 输入校验 + SQL | 用户输入拼接到SQL？参数化全覆盖？ |
| 重试 + 限流 | 重试风暴风险？退避策略？ |
| 数据增长 + 内存 | 全量加载OOM？分页/流式处理？ |

## 缺失项模式

| 看到 | 必须有 | 缺失严重度 |
|------|--------|-----------|
| 外部调用（HTTP/RPC） | 超时 + 错误处理 | ❌ |
| 事务 Begin | 事务内无IO + 有Rollback | ❌ |
| 写操作 | 幂等保护 | ❌ |
| go func / 线程 / 协程 | 退出机制 | ❌ |
| 锁 Lock | 对应 Unlock（含错误路径） | ❌ |
| 错误处理 | 日志记录 | ❌ |
| 缓存读取 | TTL + 防穿透 | ❌ |
| 重试逻辑 | 可重试判断 + 退避 + 最大次数 | ❌ |
| 文件/连接打开 | defer/close | ❌ |
| 核心业务逻辑 | 自动化测试 | ⚠️ |

## 完成标准

1. 关键路径已梳理，高风险节点已标记
2. 每个 ❌ CRITICAL 包含：具体代码位置、具体失败场景推演、修复代码
3. 每个 ⚠️ WARN 和 💡 SUGGEST 有位置和理由
4. 缺失项和跨维度风险已标记
5. 总评给出：🔴 必须修复 / 🟡 建议改进 / 🟢 通过

## 审查诚信

- "未发现问题"但不说搜了什么、看了哪些文件——等于没审。
- 是bug就说是bug。"可能需要注意"不适合描述会导致资金损失的问题。
- 量化："列表100条时增加50次查询"优于"有性能问题"。
- "测试通过了"是必要条件，不是充分条件。"我稍后清理"——经验说稍后永远不会来。

# Alpha 验证报告模板

> 由 [`alpha-validator`](../SKILL.md) Step 3 加载。字段对齐原报告（`alpha-finder` 格式）。

```markdown
# Alpha 验证报告 · {事件简述}

> **验证事件：** {事件简述}　　**验证日期：** YYYY-MM-DD
> **原报告ID：** alpha-YYYYMMDD-NN-{事件关键词}　　**原报告日期：** YYYY-MM-DD
> **原报告信心度：** x/5　　**距原报告天数：** N 天

## 验证概要

| 指标 | 数值 |
|------|------|
| 总 alpha 方向数 | N |
| ✅ 验证通过 | N |
| ❌ 已证伪 | N |
| ⏳ 仍在观察 | N |
| ❓ 数据不足 | N |
| 🎲 运气路径（已证伪中不可归因） | N |
| **准确率** | X/N（仍在观察不计入） |

> 一句话总结：这批 alpha 的验证结果和关键发现。

## 逐项验证

### 方向 A：[原报告中的标题]

- **原判断：** [从原报告摘录核心判断]
- **检验点对照：**

| 检验层级 | 原定信号 | 实际结果 | 达成？ |
|---------|---------|---------|-------|
| 即时（1-3天） | [可量化信号] | [实际数据] | ✅/❌ |
| 短期（1-4周） | [可量化信号] | [实际数据] | ✅/❌/— |
| 中期（1-3月） | [可量化信号] | [实际数据] | ✅/❌/— |

> "—" 表示时间未到，暂不判断。

- **验证结论：** ✅ 验证通过 / ❌ 已证伪 / ⏳ 仍在观察 / ❓ 数据不足
- **判断质量：** 高 / 中 / 低
- **复盘分析：** [为什么对/错？哪个假设出问题了？如果错了，归入哪种错误类型？]

### 方向 B：...

## 判断质量 × 结果质量矩阵

每个方向按 Step 3 的四象限归位。

| 方向 | 判断质量 | 验证结果 | 矩阵格 | 含义 |
|------|---------|---------|--------|------|
| 方向A | 高 | ✅ 通过 | 技能证据 | 最可信的正面样本 |
| 方向B | 中 | ❌ 证伪 | 学习样本 | 最有价值的复盘对象 |

## 复盘总结

### 正确归因
- [哪些判断对了？为什么对？是否有可复现的模式？]
- [例："卖铲人逻辑再次被验证——在科技突破事件中，上游基础设施的 alpha 确定性显著高于终端品牌"]

### 错误归因

| 方向 | 错误类型 | 根因 | 可避免？ |
|------|---------|------|---------|
| 方向A | 定价误判 | [简述] | 是/否/部分 |
| 方向B | 🎲 运气路径 | [不可归因的外部冲击] | 否（真随机） |

### 改进建议
- **可归因的（分析可避免）→ 具体流程改进。** 只更新"下次同样情况会再做"的改进项，不因一次运气改变方法，也不因一次不幸推翻系统。
- **不可归因的（真随机）→ 接受。** 不转化为流程改进——把运气硬编进流程是过度拟合。
- [从这批验证中学到什么？alpha-finder 流程中哪一步最需要加强？]
- [例："Step 4 定价程度判断数据不足时过于乐观——'基本未定价'的判断在信息不充分时应更保守"]
- [例："即时检验点设得太宽松——'板块涨幅>0%'不具备区分力，阈值应提高到>2%"]
```

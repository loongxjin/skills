# Alpha Hunter — 事件驱动的 alpha 挖掘

用户给你一个事件、一则新闻、或一个领域，你要产出一份中文投资分析报告，并尽量找到 alpha 机会。这份 skill 告诉你怎么想、怎么查、怎么写。

## 这个 skill 的灵魂：一句话

> **Alpha 来自预期差，不来自事件本身。**

事件是公开信息，公开信息基本已被定价（这就是 beta）。如果你只做"这个事件利好 A、利空 B"的罗列，你产出的是 beta，不是 alpha。真正的超额收益藏在这三个地方：

1. **传导链的后段** —— 一阶影响（直接受益）人人都看得到、定价很快；alpha 多藏在二阶、三阶（替代品、衍生需求、次生效应）。
2. **预期与现实的落差** —— 市场已经 price in 了多少？落差点就是 alpha。
3. **被忽视的反共识** —— 最拥挤的交易往往不是 alpha。

把这三句话刻在脑子里，贯穿下面每一步。

## 五个关键词（leading words）

这几个词在下面反复出现，它们是思维的锚点：

- **预期差** —— alpha 的唯一来源。每分析一个方向，都要问"这里有没有预期差"。
- **传导链** —— 主干方法。把事件的影响像树枝一样展开到一阶、二阶、三阶。
- **弹性** —— 标的排序的依据。业绩弹性 > 估值弹性 > 概念炒作。
- **拥挤** —— 反共识警示。一个方向越拥挤，越要警惕它是不是已经定价完毕。
- **证伪** —— 每一个 alpha 想法都必须配一个失效条件。没有证伪条件的想法不写进报告。

## 工具受限时怎么办（重要）

这个 skill 的灵魂是预期差，而预期差判断强依赖实时数据（市场已 price in 多少）。但联网工具并非总是可用——配额耗尽、网络中断、事件发生在数据真空期都可能遇到。硬跑会产出"我觉得"式的低质量判断，所以必须有预案。

**先认清哪些步骤依赖联网、哪些不依赖：**
- **强依赖实时数据**：Step 0（核实事件真假）、Step 2（判断 price in 程度）
- **基本靠方法论和领域知识**：Step 1（传导链）、Step 3（标的映射）、Step 4（证伪条件）

**工具失效时的降级做法：**
1. **不要停下来**——传导链、标的映射、证伪条件这些方法论步骤照样能做，它们本身就有价值。
2. **报告顶部数据状态字段必须标"部分缺失"或"完全缺失"**（见报告模板），并简述哪些没核实到。
3. **Step 2 的预期差结论降级为"定性推测"**，明确写"因未能核实当前定价水位，以下预期差判断为基于框架的推测"，不要假装有把握。
4. **信心分至少降一档**（见信心分 rubric）——数据缺失时给 4-5 分是对用户不诚实。
5. **不给目标价、仓位这类高度依赖实时数据的建议**，只到方向 + 标的 + 证伪条件为止。

这个降级方案的目的是保护诚实原则——在信息不全时，明确告诉用户"我能确定什么、不能确定什么"，比硬凑一个看似完整的报告有价值得多。

## 工作流

按 Step 0 → 5 顺序走。每一步都有一个"完成标准"，满足后才进下一步——避免在事实没核清前就急着写结论。

**过程中保持反馈：** 这个流程涉及多次联网搜索，用户需要等待。在开始时用一句话说明你要做什么，在关键节点（事实核实完、传导链推演完）简短报告进度（一两句即可），最后输出完整报告。不要闷头跑完才一次性倒出来。搜索要克制——聚焦核实关键事实和补必要数据，别在无关细节上消耗时间。

### Step 0 · 事实校准

用户给你的往往是一句话："美联储降息 50bp""OpenAI 发了新模型""XX 出政策了"。一句话可能是模糊的、过时的、甚至错误的。基于错误前提做出来的分析一文不值，所以第一步永远是核实。

**动作：**
- 用 WebSearch 核实事件**真实性、时间、量级、官方口径**。
- 补齐关键数字（降息幅度、政策金额、产品参数、伤亡规模……）。
- 判断这件事**是否已经发生**（已发生 vs 传闻 vs 即将发生，分析框架完全不同）。
- **时间锚定（关键）**：判定事件真实发生时间 vs 现在。这一步常被忽略，但它决定整个分析的节奏——同样一个事件，发生当天（首冲击，看一阶）、发生 3 个月后（利多可能出尽，看兑现/证伪）、发生 1 年后（一阶早已 price in，只看远端二阶）的分析重点完全不同。用户说"刚发生"不等于真的刚发生，用搜索核实。

**完成标准：** 你能清楚回答四件事——
1. 核心事实是什么（带数字、带时间）？
2. 是已发生、传闻、还是即将发生？**距现在多久？**
3. 市场是否已对此有明确预期（比如降息前 CME 已显示多少概率）？
4. 事件大概属于哪种类型（货币政策 / 产业政策 / 地缘 / 科技突破 / 监管 / 黑天鹅 / 其他）？类型判定后，Step 1 去 `references/chain-patterns.md` 查对应范式。

如果搜不到可靠信源，**诚实标注"事实存疑"**，并说明因此后续分析的不确定性升高。不要假装确定。

### Step 1 · 传导链推演

这是核心方法。把事件的影响像树枝一样展开，**跨资产**（股 / 债 / 汇 / 商品 / 加密互相联动）、**分层级**：

- **一阶**：直接、显而易见的影响。比如降息→成长股估值抬升；新药获批→药企收入增加。人人看得到，定价快，**多属 beta**。
- **二阶**：一阶的次生影响。比如降息→新兴市场资金回流、套息交易平仓、黄金走强；新药获批→配套的 CDMO、包装、冷链需求。
- **三阶**：更远、更隐蔽的涟漪。比如大幅降息→后续通胀反复→黄金/商品二次走强；AI 模型升级→电力缺口→核电/燃气轮机。

**为什么强调二阶以后？** 因为一阶影响太明显，已经被市场吃干净了。alpha 来自别人还没算到的环节——而那通常在传导链的后段。

**动作：**
- 对每类相关资产逐层展开，每个节点标注**方向（利多/利空/中性）+ 一句话逻辑**。
- 如果事件属于一个你熟悉的类型（货币政策、地缘冲突、科技突破、监管……），**查阅 [`references/chain-patterns.md`](references/chain-patterns.md)**，那里收录了常见事件类型的传导范式和历史上预期差错位的环节。用它来避免遗漏链条上的关键节点，而不是照搬。

**完成标准：**
- 每一类相关资产至少展开到**二阶**，关键传导链推到**三阶**。
- 输出一个文字版的传导图谱（缩进树状即可），让人一眼看清"事件 → 各阶影响 → 资产"。

### Step 2 · 预期差定位

有了传导链，现在问最关键的问题：**这里面哪些是市场还没充分定价的？**

去找三类预期差：
- **(a) 被忽视的二阶链** —— 市场注意力都在一阶，但真正有力量的影响在二阶以后。
- **(b) 共识过度定价的方向** —— 大家都看多、都买了的方向，往往没有 alpha，甚至有均值回归风险。
- **(c) 非线性 / 肥尾情景** —— 大多数人按线性外推，但某些事件会触发连锁反应或自我强化。

**预期差不能靠"我觉得"，要有锚。** 判断"市场已 price in 多少"时，尽量找可观察的信号，而不是凭感觉。不同资产能用的锚不一样，有什么用什么：
- **货币政策**：CME FedWatch、期权隐含波动率、利率期货定价
- **股票**：估值分位数（PE/PB 处于历史什么位置）、近期涨幅、卖方一致预期、北向/外资持仓变化
- **加密**：ETF 资金流、链上活跃度、稳定币市值变化、资金费率
- **商品/FX**：CFTC 持仓、期货曲线结构（contango/backwardation）、期权 skew

当联网可用时用 WebSearch 查这些数据。当无法获取时，**把预期差结论明确降级为"定性推测"**（见"工具受限"一节），不要假装有数据支撑。

**动作：**
- 对传导链上的每个方向，用上述锚判断"市场大概已经 price in 了什么"。
- 标注哪些方向有预期差，差在哪一类（a/b/c），**并注明依据的信号**。
- 这一步**聚焦"有没有预期差"这一件事**；一个方向"有多拥挤、节奏多快、怎么证伪"留给 Step 4，不要在这里展开——避免职责重叠。

**完成标准：** 每一类资产明确标注"预期差在哪、依据什么信号"，或者**诚实标注"无明显预期差，纯 beta"**——后者也是有价值的结论，说明这个方向不值得重点配置。

### Step 3 · 标的映射

把每个有 alpha 的方向落到**具体的标的**上：股票代码、代币符号、期货合约、ETF。

**动作：**
- 每个受影响方向，给出具体标的。
- 按**弹性**排序。弹性档位判断依据：
  - **业绩弹性**（最硬）：营收/利润对这件事最敏感，通常是细分龙头或纯正标的。
  - **估值弹性**：业绩关联弱但叙事强，弹性中等。
  - **概念弹性**（最虚）：蹭概念，弹性高但风险也高，往往在行情末期表现。
- 区分**龙头 vs 二线**：龙头确定性高、弹性低；二线弹性高、风险大。两者都要给，让用户根据自己风险偏好选。

**完成标准：** 每个标的注明四件事——
1. 代码 / 符号 / 合约
2. 对应传导链的**哪一阶**（一阶 = beta，二阶及以上 = 更可能是 alpha）
3. **弹性档位**（高 / 中 / 低，及其来源：业绩 / 估值 / 概念）
4. **龙头还是二线**

### Step 4 · 时序、拥挤与证伪

Step 2 回答了"有没有预期差"，这一步回答"这个机会什么时候兑现、有多拥挤、什么情况下会错"。把节奏和风险判断集中在这里，不和 Step 2 重复。

**动作：**
- 标注每个 alpha 机会的**催化剂节奏**：已兑现 / 即将兑现 / 远期，以及关键时间节点（财报、政策落地、数据发布）。
- 给每个 alpha 想法配一个**证伪条件**：什么情况出现，就说明这个逻辑错了？这是 leading word「证伪」的落地——没有证伪条件的想法，本质是信仰，不写进报告。
- 判断每个方向的**拥挤度**。拥挤度是 Step 2 第 (b) 类预期差（共识过度定价）的量化落地——一个方向越拥挤，越可能是已 price in 的 beta 甚至负 alpha。判断拥挤度同样要有锚，别靠感觉，可参考：
  - 近期涨幅（短期暴涨 = 拥挤）、估值历史分位
  - 媒体/社交讨论热度、卖方研报数量
  - 持仓数据（CFTC、北向、ETF 资金流）、期权偏度
  - 标的属性：龙头通常比二线拥挤，概念股在行情末期最拥挤

**完成标准：** 每一个 alpha 机会都配齐：
- 一个证伪条件
- 一个时间维度（**短线事件驱动** vs **中线趋势**）
- 一个拥挤度判断（高 / 中 / 低，附依据）

### 信心分怎么打

信心分不是拍脑袋，它让读者一眼知道你对这份判断有多确定。依据三个维度综合评定：

| 分数 | 含义 | 典型条件 |
|---|---|---|
| **5** | 高度确信 | 事实已核实 + 预期差清晰且有数据支撑 + 标的确定 |
| **4** | 较有把握 | 事实已核实，预期差较清晰但部分依赖推断 |
| **3** | 方向可参考，细节存疑 | 事实基本核实但预期差模糊，或事件性质有重大分歧 |
| **2** | 框架性分析，需补数据 | 事实部分存疑，或数据缺失导致预期差只能定性推测 |
| **1** | 高度不确定 | 事实存疑、事件为传闻、或联网完全失效 |

**数据缺失时至少降一档。** 给一个用户会据此决策的分数，是对用户的承诺——数据撑不起的把握，不要给。

## 几条贯穿全程的原则

- **诚实优于好看。** 找不到 alpha 就说"此事件多为 beta，无明显预期差"，这比硬凑一个 alpha 有价值得多。用户的信任来自你的诚实。
- **数字优先于形容词。** "大幅利好"是废话，"降息 50bp、超出市场预期的 25bp"才是信息。
- **跨资产联动。** 很多 alpha 来自资产之间的传导（股→债、商品→汇、传统金融→加密），别把每类资产孤立分析。
- **结论先行。** 报告先把"一句话结论"亮出来，再展开论证。读者时间宝贵。
- **不要给具体仓位和目标价。** 你是分析师不是投顾，只到"方向 + 标的 + 弹性 + 证伪条件"为止。

## 输入太模糊时

如果用户的事件描述模糊到没法做有意义的分析（比如"最近科技股怎么样"），先用 WebSearch 补上下文，并和用户确认你理解的"事件"是否正确，再开始分析。宁可多问一句，不要基于猜测跑完整个流程。
